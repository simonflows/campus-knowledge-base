# Импорт проверенного пакета карточек 0.9.5

Перед применением подготовьте и испытайте резервную копию, выполните миграцию таблиц и повторите этот сценарий на отдельной базе. Сверка пакета фиксирует проверку источников. Согласование, которое должен дать вуз или конкретный сотрудник, проводится через штатный процесс.

## Команды

Выполняйте из корня проекта с настроенным подключением к нужной DynamoDB или Document API. Аргументы содержат только пути к файлам.

Если запуск выполняется в production-образе, передайте оба JSON в контейнер через монтирование только для чтения и укажите их пути внутри контейнера. Образ содержит сам CLI. Сохраняйте исходные байты пакета при переносе файлов.

```text
node --import tsx scripts/import-reviewed-package.ts data/pilot-0.9.5-candidates.json data/pilot-0.9.5-verification.json
node --import tsx scripts/import-reviewed-package.ts data/pilot-0.9.5-candidates.json data/pilot-0.9.5-verification.json --apply
node --import tsx scripts/import-reviewed-package.ts data/pilot-0.9.5-candidates.json data/pilot-0.9.5-verification.json --apply --sync
```

Первый запуск проверяет пакет и читает совпадения по ID и версиям в выбранной базе. Второй записывает допустимые карточки. Третий после этапа записи отдельно запускает выгрузку подходящих утверждённых карточек. Для восстановления частичной выгрузки используйте третью команду с теми же файлами.

## Валидация и запись

- Сверяются SHA-256 точных байтов пакета и `packageSha256` файла проверки. Все ID пакета должны встретиться ровно один раз в `approvedIds` или `pendingIds`. Для изменения текста или состава требуется вновь сверенный пакет с новым хешем.
- Статус `approved` допустим для записи из `approvedIds`, предложенной как утверждённая, с известными обязательными параметрами и без ожидаемых согласований участников. Совместные карточки этого пакета сохраняются на подтверждении. Для карточек, требующих согласований, сохраняются явно указанные ID вузов или список подтверждающих вузов совместного проекта.
- Указанные в тексте владельцы сохраняются. Персональные назначения остаются пустыми до подтверждения. Источники сохраняют название издателя, HTTPS-ссылку и известную дату публикации. Происхождение записи включает хеш пакета, сведения независимой проверки, доказательства и известные открытые вопросы. Время выполнения команды фиксируется отдельно.
- У утверждённой карточки и её неизменяемого снимка — одна транзакция с условием отсутствия обоих ключей. В качестве основания сохраняется текст из пакета и роль координатора, действующего по поручению владельца. Черновик сохраняется без снимка публикации и без подтверждений участников.
- Ранее созданные карточки и версии остаются по своим ID. Повтор с тем же содержимым учитывается как `preserved`. Отличающаяся карточка отмечается как `collision`. Несогласованность записанного снимка или уже существующий снимок при отсутствии карточки отмечается как `snapshot-conflict`. Эти ситуации требуют операционной сверки.

## Выгрузка и результат

Перед каждой выгрузкой инструмент заново читает утверждённую карточку и проверяет её публичное содержимое. При повторе уже существующие записи остаются в отчёте как сохранённые. Полный результат требует подтверждённых Markdown и CSV этой редакции. Черновики пропускаются. Изменённая или конфликтующая карточка пропускается со статусом `skipped-changed`.

Отчёт содержит ID, статусы действий, хеш пакета и счётчики. Код выхода `0` означает выполненную проверку или запись. При `--apply` код `2` сообщает о сохранённых конфликтах, незавершённой записи или неподтверждённой выгрузке. Код `1` сообщает о невозможности проверить вход, подключиться к базе или завершить чтение. Отчёт dry-run может содержать конфликты при коде `0`, поскольку это результаты проверки.

Запись карточки и выгрузка выполняются раздельно. При отказе Диска данные и прошлая полная копия сохраняются. Сводка показывает актуальность после отдельной сверки с базой. [Проверка сводки и восстановление файлов](release-0.9.5-disk.md)
