До этого локальный сервер сохранять; прежний запрет выключения отменён владельцем.

## Результат

**Актуальное уточнение владельца:** основной вход выбран через Яндекс ID (OAuth), без писем Канона. Email/password остаётся необязательным выключенным вариантом. Первый OAuth-вход создаёт только автора; права сотрудника выдаёт координатор. Сначала использовать/проверить существующие приложения основного аккаунта `mlnkws`, где находится облако. Root ошибочно открыл форму в новом `canon-noreply`, но приложение НЕ создавалось, форма закрыта. Созданный контактный ящик `canon-noreply@yandex.ru` не используется для шаблонных регистрационных рассылок. Политика обычной Яндекс Почты проверена, прежняя SMTP-рекомендация отозвана. Пункты ниже про письма описывают исходный план; приоритет имеет это уточнение.

OAuth: authorization code, state+PKCE S256, точный callback `https://canon.midis.ru/api/auth/yandex/callback`, только login:info/login:email. Сессия приложения остаётся отзываемой v3. Профили адресуются хешем namespace Yandex UID, не email; совпадение контактной почты не объединяет аккаунты/владение. Контактный default_email не объявляется подтверждением email. OAuth-токены не хранятся постоянно. Секрет клиента — runtime/Lockbox, callback query не попадает в access logs; no-store/no-referrer. Имена окончательных флагов согласуются с исполнителем до настройки.

1. Самостоятельный вход через Яндекс и отзыв сессий. Email/password и письма остаются выключенным запасным вариантом. Базовый автор работает со своими закрытыми статьями, редактором, проверкой, утверждённой аналитикой и экспортом. Запросы изменения/подтверждения, карточки и согласования доступны только назначенным сотрудникам; должность/вуз при регистрации не дают полномочий. Координатор явно назначает доверенные роли и контуры. Существующие персональные ID, карточки и история сохраняются.
2. Фильтры внутри папки сохраняют её область. Категории различаются значками. Учебные тексты включают корректный пример из текущих утверждённых версий, проверяемый обычным движком без подмены результата.
3. Проверенный цикл создания/редактирования карточки, выбора контуров, обязательных согласований и запросов. Подтверждённые дефекты исправляются с регрессиями; реальные ожидающие согласования не обходятся.
4. Помощник кратко отвечает с источниками; отдельный включаемый интернет-поиск возвращает внешние ссылки с явной маркировкой. При первом включении — подтверждаемое предупреждение, затем сохранённое предпочтение. Внешние сведения не становятся утверждёнными фактами автоматически.
5. Аккуратная закреплённая шапка, выразительные состояния поиска/ИИ и микроинтеракции в существующем стиле; клавиатура, touch, reduced motion и мобильные размеры.
6. Версия 1.0.0, безопасная работа YDB/Lockbox/Диска/почты, резервирование, проверенный выпуск на https://canon.midis.ru/.

## Разделение работы

- AUTH100 (Sol 6.2/high): аккаунты, сессии, права и формы; единственный автор auth/schema. До реализации передаёт контракт и совместимость.
- UI100 (Sol 6.2/high): область фильтров, значки, шапка, обратная связь и анимации рабочих экранов. Помощник и auth-формы исключены из его записи.
- WF100 (Sol 6.2/high): независимый аудит согласований/backend; сначала доказательства и тесты, затем явно выделенные файлы исправлений.
- Оркестратор: облако, интернет-поиск, лимиты ИИ, корректный учебный пример, интеграция, CI, выпуск и документация. Финальное независимое ревью отдельной волной на итоговом diff.

## Данные, API и совместимость

- Только DynamoDB/YDB Document API. Добавочные таблицы аккаунтов: `ACCOUNT_IDENTITIES`, `ACCOUNT_SESSIONS`, `ACCOUNT_RATE_LIMITS`, ключ `id/S`, без зависимости от GSI и своевременной TTL-очистки. Окончательные имена сверяются с `TABLE_SCHEMAS` до миграции. Для устойчивого ограничения ИИ добавочная таблица/счётчики согласуются до записи.
- Нормализованный email резервируется условной записью, пароль хранится как salted scrypt; токены только в виде криптографического хеша с назначением и сроком. Пароль устанавливается после доказательства владения email явным POST; переход по GET не расходует токен. Смена пароля отзывает старые сессии. Лимиты и ошибки не раскрывают наличие адреса. HTTP cookie сохраняет `__Host-vibecraft-*`, Secure, Path=/, без Domain.
- Существующие pilot-ключи/ID и подписанные сессии остаются совместимы в переходе. Нельзя автоматически присваивать существующее владение по выбранному логину/email/вузу. Новые аккаунты по умолчанию `author`; платный ИИ доступен после действующего входа; подтверждение контактной почты не имитируется. Проверки прав выполняются сервером для всех маршрутов, включая прямые запросы.
- История карточек, ревизии, tombstones, согласования и обязательные стороны не преобразуются массово. Добавочные API-поля имеют безопасные значения по умолчанию. Отказ рабочей БД — 503, без учебной подмены. Browser demo изолирован от рабочих API, писем, Диска и платного ИИ.
- Интернет-поиск — явный режим, ограниченный размером вопроса/временем/частотой и устойчивой квотой пользователя и сайта. В поиск отправляется вопрос, без закрытых карточек/черновиков. Внешние URL валидируются; произвольные адреса сервер не загружает. Ссылки и внешние ответы отделены от утверждённых источников.
- Диск используется для разрешённых экспортов; пароли, сессии, почтовые токены и архивы аккаунтов туда не выгружаются. Секреты не попадают в исходники, клиент, отчёты и логи; применяются runtime/Lockbox и минимальные IAM-права.

## Порядок миграции и выпуска

1. Проверить фактическую VM, SSH, IAM, DNS, Postbox, Lockbox, готовность YDB, свободное место. При необходимости расширить диск с сохранением данных и прежнего rollback-образа. Не выполнять широкую очистку Docker/рабочих данных.
2. Реализовать и проверить изменения на синтетической изолированной базе. Миграция только добавляет таблицы. Проверить прежние данные/сессии и новый цикл аккаунта, ошибки доставки/БД, повтор токенов и смену роли. Основной OAuth не зависит от писем или доступа к DNS МИДиС. Callback и минимальные scopes настраиваются в основном аккаунте владельца.
3. Итоговые host check/offline/build, реальный UI/API, безопасный аудит и независимое ревью. Получить точный неизменяемый CI image и успешные обязательные проверки; публикация разрешена пользователем, ослабление CI не разрешено.
4. Перед рабочей миграцией — свежая защищённая копия всех старых таблиц, проверка и фактическое восстановление в изолированный префикс. Учесть новые таблицы в механизме последующих полных копий. Миграцию выполнять штатно через Docker exec. Сверить наличие/ключи/готовность всех таблиц.
5. Выпустить точный проверенный образ с блокировкой/защитой записи, существующими TLS/доменом/renewal и фиксированным rollback. Проверить публичные версии/ready, авторизацию, основной цикл, начало и полный цикл OAuth-входа на контролируемом аккаунте, реальные ограниченные вызовы ИИ/поиска и отсутствие непредусмотренных изменений данных.

## Восстановление

Старые 0.9.5/48ce writers запрещены из-за tombstones. До выпуска определить совместимый 0.9.9 rollback: новые таблицы сохраняются; он не понимает новые v3 сессии и не должен их авторизовать. Возврат приложения не откатывает БД/пользовательские изменения. После появления аккаунтов старый UI временно не предоставляет email-вход: это ограничение rollback, требующее исправленного 1.0.x, а не удаления аккаунтов. Если изменение окажется несовместимым с текущими данными/согласованиями, выпуск останавливается до проверки корректирующего пути. Рабочее восстановление из резервной копии — только с явным решением и оценкой последующих записей, не автоматический шаг.

## Приёмка

- RED→GREEN для подтверждённых ошибок, тесты одноразовости/сроков/гонок/изоляции/прав и отказов БД/провайдера.
- Реальные локальные API и браузер: Яндекс→callback→личный аккаунт→свой черновик→logout; запасной email/reset — синтетические проверки при выключенном production-флаге; запреты author на карточки/запросы, повышение только координатором; прежний pilot-доступ и владение.
- Фильтры в вузе остаются в вузе; корректный пример даёт G>0/R0/Y0 обычным движком; изменённая цифра обнаруживается. Интернет переключается только после первого подтверждения и имеет внешние ссылки.
- UI 320/390/768/1440px, клавиатура, reduced motion, без переполнения/ошибок консоли; browser demo без рабочих запросов и платных вызовов.
- Host/CI обязательные проверки проходят; независимое ревью итоговой версии без блокирующих замечаний. Проверены резервная копия/изолированный restore, место, точный image, TLS/ready и живые интеграции. Непроверенные условия явно отмечаются; абсолютная «невзламываемость» не обещается.
