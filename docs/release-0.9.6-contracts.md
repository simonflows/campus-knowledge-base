# Контракты реализации 0.9.6

## Совместимость и выпуск

Существующие записи YDB, таблицы и утверждённые версии сохраняются. Формы запросов и основные поля ответов API сохраняются; интерпретация/AI/ссылки добавляются необязательными полями. Исправление потерянного ограничения вправе сузить неверную выдачу или явно запросить уточнение. Рабочая миграция только добавочная после тестов/backup; необратимых преобразований не планируется. Образ0.9.5 сохраняется; при новых полях не включать прежний writer, если он обходит новое согласование. Подробное восстановление дописывается при выборе схемы согласований, до её кода.

Матрица ТЗ строже прежнего публичного пилота: аналитика теперь требует сотрудника (API401 без входа,403 для гостя; страница ведёт на вход). Гость сохраняет просмотр и обычную проверку текста. Browser-only демо позволяет попробовать все сценарии без рабочего аккаунта. Это намеренное ужесточение доступа; старые анонимные аналитические тесты должны войти синтетическим сотрудником, проверки отказов остаются явными.

## Запросы

- `searchKnowledgeCards(cards, query)` и `getSearchFragment` сохраняют сигнатуры. Поступают только ACL-отфильтрованные актуальные карточки. Поиск по именам/оборудованию/алиасам не использует stopFormula и URL как доказательство наличия объекта.
- `buildAnalyticsReport(query,cards,types)` сохраняет форму таблицы/summary. Добавляет интерпретацию, если существенное условие не поддержано. Числа/строки/сводки вычисляет приложение по структурным полям и всем сохранённым условиям. Нельзя молча игнорировать KUKA/неизвестную сущность/отрицание.
- Примеры запросов выводятся только после выполнения того же построителя на доступном наборе; пустая база имеет собственное пустое состояние.

## AI и источники

- Сервер заново читает утверждённые карточки при каждом пользовательском действии. Источник содержит cardId, вычисленную versionId, безопасные поля и точный фрагмент; URL строит сервер. Личные поля/служебные метаданные/неутверждённые версии не передаются.
- Статьи — только утверждённые смысловые блоки с revisionId/chunkId; они не становятся источником новых чисел. Живая генерация использует текущие карточки; исторический паспорт проверки остаётся привязан к сохранённой редакции.
- Строгий ответ модели: разрешённые ID/ссылки и дословные цитаты валидируются, произвольные HTML/URL и инструкции внутри данных не исполняются. Название известной карточки само по себе не подтверждает остальные тезисы.
- Обычный результат не исчезает при отказе/тайм-ауте/отмене. Дополнительный AI реально меняет интерпретацию/вывод только с проверенной опорой; непроверенные тезисы сохраняют статус «нет подтверждения». AI не получает инструментов записи/публикации.
- Один общий ограничитель для платных действий: сотрудник, same-origin, ограничение параллельности/частоты/размера, signal HTTP и тайм-аут. Автотесты — без платных запросов. Публичное демо — без платного провайдера, с явной демонстрационной пометкой.

Документация провайдера проверена: [структурированный Completions API](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-structured). Поддержка схемы конкретной моделью не считается доказанной до безопасной проверки; локальная проверка ответа обязательна независимо от API.

### Интерпретация аналитики

- `useAi` запускает один запрос через общий лимит. Модель получает исходную формулировку, разобранные ограничения, разрешённые типы и утверждённые карточки. Её ответ содержит только предложенную формулировку, код уточняющего вопроса или дословные цитаты. Строки, показатели и сводки рассчитывает приложение.
- Автоматически применяются эквивалентные формулировки и явно распознанное уточнение «вуз + название» до паспорта того же вуза. Сервер проверяет все явные фильтры, отрицания, выбор по оборудованию и значимые термины, включая многословные названия. При потере условий или неподдерживаемой логике показывает уточняющий вопрос без широкой выдачи. Нераспознанная отрасль остаётся в ограничениях.
- После ответа перечитываются карточки и определения типов. При изменении набора или версии используется актуальный расчёт по исходному запросу. При недоступности модели сохраняется обычный расчёт, в том числе если исчерпан лимит. При принятии уточнения интерфейс показывает исходный запрос и формулировку для расчёта. Цитаты проверяются дословно по карточкам выбранных строк, ссылки ведут к их версиям.

## Демо и доступ

**Уточнение владельца после первого анализа:** демо хранится только на компьютере посетителя в браузере. Серверная песочница/отдельный Docker DynamoDB отменены до реализации. Отдельная страница `/demo` имеет client-only состояние с версией, проверкой формата, сохранением после reload и сбросом. Демо не меняет рабочую сессию/cookie, `process.env`, YDB или Диск. Начальный набор — только публичные утверждённые карточки и явно учебные примеры; из браузера в этом режиме не отправляются запросы записи в рабочие API и платные провайдеры. Не подменять глобальный fetch. Режим показывает реальные чистые алгоритмы поиска/аналитики/проверки и локальный редактор, а ответы без внешней модели честно обозначаются как демонстрационные.

## Дополнительная сверка полного ТЗ перед выпуском

Живая приёмка b6bbdfc: пять вызовов безопасно перешли к обычному результату,0 полезных. Диагностика подтвердила HTTP200 и валидный JSON; один ответ указывал правильные sourceId/factId, но пересказывал поле placementStatus, нарушая дословность. Внутренний протокол модели расширяется ссылкой `{sourceId,factId}` без quote: сервер разрешает точную пару только в отправленном снимке и возвращает полное каноническое поле с настоящей версией. Переданный legacy quote всё ещё проверяется строго; неизвестные IDs, чужое поле/объект и неподдержанный тезис не принимаются. Публичный ответ и схема данных остаются прежними. Короткое целое поле «МИДиС» допустимо, вырванный короткий фрагмент длинного поля — нет. Фактчекинг сохраняет проверку каждого утверждения и защиту обычных красных замечаний; модель не получает полномочий менять данные. Проверить fake IDs, недоказанные числа/действия, отрицания, поля размещения/другую лабораторию, смену версии и реальные ограниченные вызовы после сборки.

Повторный независимый обход кандидата b60c141 обнаружил непокрытые декларации без глаголов (бюджет, проценты, количество, партнёр), общую сверку имён/должностей и отсутствие явного выбора утверждённого блока в действующем редакторе. Кандидат не допускается к слиянию/рабочей записи до исправлений и повторного ревью.

Обычный фактчек обязан проверять каждую числовую и атрибутивную декларацию: неизвестное значение остаётся жёлтым, явная подмена подтверждённого поля связанного объекта — красным, совпадение — со ссылкой на источник. Узнанное название/ID не подтверждает следующие строки; цифры внутри ID не считаются метрикой.

Выбор основы генерации — только текущий утверждённый материал и его точный блок. Сервер проверяет articleId/chunkId/approved revision, сохраняет и показывает происхождение формулировки. Библиотека служит основой подачи, актуальные факты по-прежнему проверяются по карточкам. Недоступная, снятая или изменённая опора отвергается; старые утверждённые материалы без revision обозначаются как исторические без выдумывания ID. Новые поля ссылок необязательны и добавочны, старые документы читаются, DDL не требуется. Синтетические проверки: явный выбор, запреты чужого черновика/подмены/stale, восстановление метаданных и прежний запрос без основы. Восстановление — предыдущий код на отдельной копии; рабочая база и действующие согласования не изменяются.

Правила SEO/GEO проверяются по фактической генерации: самодостаточный лид до1000 знаков, участники и контур при наличии в карточке, практический смысл без выдумок, смысловые H2/H3 и компактные блоки. Одно повторённое название не считается готовой статьёй; при неполной опоре нужен честный отказ или проверенная локальная сборка.

## Уточнение живой приёмки 23 ноября

Живой провайдер вернул HTTP 200 и корректный JSON, но расширил запрос KUKA, выбрал лишнюю лабораторию для паспорта и добавил в правку заголовка число из описания. Поэтому внутренний запрос аналитики передаёт `canonicalPlan`: исходную строку уже распознанного запроса или только существующее доказуемое уточнение «вуз → паспорт». Модель получает факты исключительно выбранных планом карточек с прежними sourceId/factId; сервер требует точного совпадения query с планом и проверяет каждый источник, полное поле, выборку и актуальность всего снимка. При пустом плане допустимы только JSON null, код уточнения и пустые quotes. Ложное `ready` и молчаливое удаление плохих цитат не допускаются.

Для правки точно выделенного утверждённого заголовка модель получает только это название. Ответ сохраняет слова/порядок, допускает оформление и короткую атрибуцию, но не другой факт или новый абзац. Остальные фрагменты и варианты сохраняют прежний полный контекст; ограничения чисел/ссылок/публикации не ослаблены. Это частный формат запроса модели: внешний API/старые клиенты/данные/DDL остаются совместимыми. Цитатная проверка и явное применение пользователем обязательны; тест заголовка не подтверждает свободное переписывание статьи.

Скачивание резервной сводки допускает до двух переходов по HTTPS на официальные `*.storage.yandex.net` с проверкой каждого адреса. OAuth используется только у cloud-api при получении метаданных. Нестандартные порты, userinfo, фрагменты и чужие домены отклоняются; дедлайн, лимит 8 МБ, SHA и поведение при 404 сохранены. [Официальные домены скачивания](https://yandex.ru/support/yandex-360/business/admin/ru/network-settings). Правила загрузки не расширены.

## Права

PR создаёт черновики, но не получает право изменять утверждённую карточку из-за авторства или своего вуза. Подтверждение совместного участия — от ответственного участника, не любого вошедшего PR. Совместная карточка физически одна в `02_Совместные_проекты`, папки вузов показывают ссылки. Министерство/РИОН/ЧКК получают явное согласование своих параметров по матрице ТЗ без молчаливого права переписать чужую карточку. Конкретный добавочный workflow и совместимость старых записей закрепляются перед изменением.
