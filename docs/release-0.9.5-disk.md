# Сводка папки на Яндекс Диске

Карточка и статья сохраняют свой статус выгрузки в `diskSync`. Совместимые поля `filePath`, `summaryPath`, `sourceUpdatedAt`, `sourceRevisionId` и `lastSuccessfulExport` сохраняются. В `workflow-records` добавляется по одной записи `disk-registry` для каждого сочетания корня Диска, папки и вида материалов. Ключ вычисляется из пути. Схема таблицы и существующие записи при этом не меняются.

## Подтверждение выгрузки

1. Приложение сохраняет номер попытки на карточке или статье и читает предыдущий указатель папки.
2. Оно загружает Markdown согласованных данных, указатели совместного проекта и CSV. Пути содержат хеш содержимого. Запоздавшая попытка может завершить запись своего файла. Повторная отправка по этому же пути записывает те же данные.
3. После загрузки приложение повторно читает утверждённые данные папки. Оно сверяет состав, содержание и комплектность строк. Комментарии правки и данные о сроке сверки карточки не меняют её опубликованное содержание.
4. Статус попытки и указатель папки подтверждаются одной транзакцией DynamoDB или Document API. Условия проверяют версию материала, номер его попытки и прочитанный указатель папки. Запоздавшая попытка не заменит новый подтверждённый указатель.
5. При изменении состава папки или указателя текущая попытка может один раз повторить выгрузку со свежими данными в пределах исходного тайм-аута. Если данные продолжают меняться, попытка остаётся в ожидании ручного повтора. Когда изменился сам материал или его попытка, прежний запуск получает конфликт. Оператор обновляет страницу и повторяет выгрузку новой версии.

Частичная ошибка, например успешная запись Markdown и отказ CSV, сохраняет предыдущий подтверждённый указатель и путь к последней полной копии материала. Подтверждённая сводка содержит статус строк. Если отдельная строка ожидает выгрузки, полный комплект файлов для этой строки ещё не подтверждён.

## Как найти и восстановить копию

- В панели Диска откройте «Сверить сводку папки». Авторизованный `GET /api/knowledge/cards/:id/sync` или `GET /api/articles/:id/sync` возвращает путь, время подтверждения, время сверки и результат сравнения. Запрос только читает базу. Прежний `POST` возвращает карточку или статью со статусом выгрузки.
- Статус «Сводка папки совпала с опубликованными данными» относится ко времени этой сверки. Если данные изменились, панель показывает прежнюю полную сводку и её дату. Используйте «Повторить выгрузку», чтобы сохранить более свежую.
- Файлы новой попытки после частичной ошибки остаются в папке со своими именами. До подтверждения сводки выбирайте путь из приложения. При недоступности приложения оператор вручную сверяет данные строк и наличие указанных файлов. Сортировка имён и время загрузки не удостоверяют актуальность.
- Старые копии остаются доступны по сохранённым путям. До первой успешной выгрузки после обновления общая подтверждённая сводка папки может отсутствовать. Панель показывает последнюю известную полную копию материала. В режиме локального демо указатель папки в рабочей таблице не сохраняется.

Согласованное чтение DynamoDB по отдельным записям не создаёт транзакционный снимок всей папки. Изменение другой записи между повторным чтением и записью указателя может сделать готовую копию устаревшей. Чтение указателя снова сопоставляет её с доступным опубликованным корпусом. Общей транзакции с Диском нет. Сверка базы не проверяет ручное перемещение или удаление файлов на Диске после успешной загрузки.

## Проверка

Целевой тест `scripts/test-canon-disk-race.ts` использует одноразовую DynamoDB Local и подменённый транспорт Диска. Он задерживает передачу старого CSV, меняет карточку или согласованную статью, завершает новую выгрузку первой и затем проверяет пути и фактически записанные байты. Отдельно проверены изменение после повторного чтения, условное подтверждение указателя и частичная ошибка с восстановлением после повтора. Рабочие YDB и Диск проверяются при приёмке выпуска.
