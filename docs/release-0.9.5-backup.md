# Снимок и восстановление базы «Канона» 0.9.5

Команды работают через Document API. Снимок содержит данные всех объявленных таблиц приложения, определения ключей и индексов, число строк и SHA-256 каждой таблицы и всего архива. JSON сохраняет типы DynamoDB, точные числа и бинарные данные. Список таблиц берётся из `TABLE_NAMES` выбранного выпуска.

## Создать и проверить снимок

1. Подготовьте каталог вне репозитория, с доступом только у оператора резервирования. На Linux используйте каталог с правами `0700`. На Windows ограничьте права каталога через ACL. Архив содержит полные данные, включая закрытые черновики и запросы.
2. Остановите все процессы записи в исходную YDB, включая приложение, импорт и фоновые операции. Дождитесь завершения уже начатых записей. Последовательный `Scan` с `ConsistentRead=true` читает все страницы каждой таблицы. Согласованность нескольких таблиц обеспечивается паузой записи.
3. Передайте `DOCUMENT_API_ENDPOINT`, `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY` из штатного хранилища в окружение процесса. Регион по умолчанию `ru-central1`, при необходимости задаётся `DOCUMENT_API_REGION`. Для снимка достаточно разрешений на `DescribeTable` и `Scan`. Запустите из каталога выпуска с установленными зависимостями.

```sh
node --import tsx scripts/database-backup.ts snapshot /secure/backup/kanon-before-095.json --writers-stopped --pre-0.9.5
node --import tsx scripts/database-backup.ts verify /secure/backup/kanon-before-095.json
```

`--pre-0.9.5` нужен только до добавочной миграции 0.9.5. Он исключает `knowledge-card-versions` и `workflow-records` и требует, чтобы обе таблицы отсутствовали. После миграции опустите флаг. Отсутствие любой таблицы, входящей в выбранный набор, останавливает создание архива.

Скрипт создаёт файл только по новому пути с правами `0600` на POSIX. Для разового запуска из готового контейнерного образа используйте закрытый каталог с доступом на запись доверенному оператору. При необходимости root-владения архивом запустите разовый контейнер от root и смонтируйте этот каталог отдельно. Значения настроек передавайте тем же защищённым способом, что и для штатного приложения. Монтировать закрытый каталог внутрь репозитория и включать его в сборку образа нельзя.

`verify` работает с файлом без подключения к базе. Проверка включает версию формата, точный набор таблиц и схем, уникальность идентификаторов, количества и контрольные суммы. Пределы этого инструмента — 64 МиБ на файл, 100 000 записей в архиве и 2 МиБ JSON на запись. Несовместимая схема, повреждение или превышение предела останавливают операцию. Сохраните SHA-256 из вывода отдельно в журнале выпуска. Контрольная сумма подтверждает целостность содержимого, а доступ к артефакту и журналу защищает доверенный оператор. После успешного создания и проверки файла можно вернуть запись, если порядок миграции этого допускает.

## Проверить восстановление в изолированных таблицах

1. Передайте в окружение адрес и доступ к разрешённой временной базе либо к утверждённому набору временных таблиц. Для проверки совместимости можно использовать исходный Document API с отдельным временным префиксом, одобренным оператором.
2. Выберите новый префикс `qa095-<уникальный-суффикс>-`. На время проверки исключите других писателей для этого префикса.

```sh
node --import tsx scripts/database-backup.ts restore /secure/backup/kanon-before-095.json --prefix qa095-backup-20261122-a1-
```

Скрипт проверяет, что под указанным префиксом нет таблиц, и отдельно проверяет отсутствие каждого ожидаемого имени. Затем создаёт таблицы и записывает строки условно, без замены существующего ID. После записи повторно читает схемы и все записи, сверяет количества и контрольные суммы. Успешный вывод содержит статус `restored`, количества и SHA-256. Проверьте связи, разрешённое чтение и тестовую запись отдельно в пределах временной среды. Приложение можно подключить к таблицам с исходными именами в отдельной БД, а сквозная проверка префикса выполняется через Document API.

## Аварийное восстановление в отдельную пустую БД

Сначала сверьте адрес выделенной цели и её разрешения. Укажите её в `DOCUMENT_API_ENDPOINT`, передайте права только на эту БД и оставьте любые приложения отключёнными до приёмки. Используйте явный флаг:

```sh
node --import tsx scripts/database-backup.ts restore /secure/backup/kanon-before-095.json --disaster-recovery
```

Этот режим разрешает исходные имена только на другом endpoint. Любая существующая таблица в цели останавливает операцию. Переключение приложения и восстановление его учётных записей, настроек Lockbox и Nginx выполняются отдельно по [регламенту развёртывания](../DEPLOY.md). План выпуска и шаги проверки совместимости описаны в [плане миграции](release-0.9.5-data-migration.md).

При ошибке `target-write` или `target-verification` цель может содержать часть созданных таблиц или строк. Повтор в ту же цель будет отклонён. Сохраните её для разбора и повторите операцию с новым пустым префиксом или новой пустой БД. Скрипт не удаляет таблицы. При `archive-write` проверьте место и права, затем выберите новый путь. Успешное восстановление в DynamoDB Local не заменяет такой же прогон через YDB Document API.
