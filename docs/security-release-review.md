# Проверка безопасности перед пилотом «Канона»

Проверены исходники входа, ролей и серверных маршрутов, модель черновиков и межвузовских запросов, конфигурация выпуска и зависимости приложения. Для проверки поведения использовались тестовые аккаунты и временная база. `npm audit --omit=dev` на момент проверки вернул ноль известных уязвимостей в зависимостях исполнения.

## Исправления

| Номер | Приоритет | Проблема и результат |
| --- | --- | --- |
| 1 | Высокий | При совпадении имени у сотрудников разных вузов доступ к карточке теперь учитывает организацию. Однозначные старые подписи сохраняют доступ. Для новой карточки из межвузовского запроса и при сохранении в форме имя остаётся вместе с организацией. [Права владельца](../lib/auth.ts), [реестр доступа](../lib/pilot-auth.ts), [форма](../components/knowledge/knowledge-card-form.tsx), [запросы](../lib/information-requests-models.ts) |
| 2 | Средний | После установки или смены демонстрационного PIN старая сессия администратора отзывается. При обновлении экземпляра с уже включённым PIN администратору нужно войти заново. Production-шаблон отключает демонстрационный вход. [Привязка сессии](../lib/pilot-auth.ts), [Compose](../deploy/compose.prod.yml) |
| 3 | Средний | Вход по SSH проверяется во втором сеансе до изменения настроек. Первичный сертификат выпускается через временный HTTP-блок, затем применяется полный прокси, а при продлении перезагружается Nginx. Это убирает зависимость первого запуска от ещё не выданного сертификата и снижает риск потери административного доступа. [Серверная инструкция](../DEPLOY.md) |

## Условия перед открытием сайта

- Проверить, что Nginx принимает HTTPS, приложение доступно только через него, а доверенный прокси сам записывает IP клиента. Проверку доступности таблиц провести с правами сервисной учётной записи. Текущий лимит входа хранит попытки в памяти одного процесса. При добавлении реплик потребуется общий лимит на входе. [Серверный вход](../lib/auth-server.ts), [предварительная проверка](../deploy/preflight.ts), [проверка таблиц](../scripts/check-deploy-storage.ts)
- Сверить реестр владельцев перед выдачей рабочих доступов. Если совпадают и полное имя, и организация, текстовая подпись не даёт индивидуального разграничения старых карточек. До выдачи доступа нужен различимый ярлык владельца. Для дальнейшего перехода к постоянным идентификаторам потребуется миграция со сверкой прежних записей. [Права владельца](../lib/auth.ts), [порядок выдачи ключей](../DEPLOY.md#pilot-access)
- Пробный запуск Flash провести на открытом учебном тексте. Облачная модель получает специально переданные ей исходные сведения. Изменение клиента проверялось на подменённых ответах. Для рабочих материалов согласуйте допустимый состав данных с оператором. [Клиент ИИ](../lib/yandex-ai.ts), [настройка хранения запросов AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging)
- Подтвердить рабочий путь восстановления YDB, прежде чем приглашать пользователей. Документные таблицы и отдельный перенос в S3 требуют проверки на облачной базе. [Проверка восстановления](../deploy/backup/README.md)

Результат относится к изменениям в репозитории и локальному запуску. Состояние будущей ВМ, реальных ключей, сети, облачных прав и нагрузка проверяются на этапе выпуска.
