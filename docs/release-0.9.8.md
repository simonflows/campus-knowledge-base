# Канон 0.9.8

Статус на 24 ноября 2026: первое переключение на 0.9.8/5da7cd0 прошло операционные проверки, но окончательная приёмка открыта. На реальных утверждённых данных обнаружены ошибки границ и контекста доказательства вместимости; готовится исправленный образ с повторным CI, ревью и свежим backup/restore. ПК до завершения не выключать.

## Изменения

- Фактчекинг: полный семантический разбор вместо статистической выборки длинной статьи. Извлечение утверждений отделяется от подбора утверждённых карточек и проверки доказательств. Точные фрагменты, контекст, unknown, охват и версии источников остаются видимыми. Неполный или недопустимый ответ не является подтверждением текста.
- Исправления остаются точечными: интервью и цитаты не заменяются новым текстом из карточки. Для свободных материалов используется сохранение авторского текста; генерация нейросетью всего интервью не обещается. Короткая проверяемая формулировка по карточкам сохраняет существующий опциональный ИИ-режим.
- Главная сохраняет прежний стиль: пропорциональные контуры на телефоне, более спокойные переходы, устойчивые показатели и небольшой блок сведений из паспорта.
- Помощник предлагает три меняющихся примера. Выбор примера не должен уничтожать набранный вопрос; источники и целевые переходы работают также без внешнего ИИ и в изолированном демо.
- Редактор подсказывает следующий шаг; создание черновика доступно на телефоне. «Инфоповоды» называются «Подборки для публикаций». Роли, согласование и функции сохранены.
- Версия в подвале открывает небольшой диалог изменений; Enter/Escape и возврат фокуса поддерживаются.

## Совместимость

Схема DynamoDB/YDB и роли не меняются; миграция не нужна. Отчёты API сохраняют прежние поля, новые метрики охвата добавляются совместимо. После ИИ проверяется актуальность всего утверждённого набора источников. Ссылки открывают использованные версии карточек. Демо использует браузерные данные и не вызывает рабочий API, платный ИИ или Диск.

## Порядок установки

1. Проверить финальный Git diff и staged diff. Слить PR только после обязательного strict Quality gate. Сохранить exact успешный push run/head SHA и проверенный image artifact, проверить SHA256 архива и image ID/labels.
2. На ВМ загрузить именно этот образ, без повторной сборки. Свежий каталог исходников из `git -c core.autocrlf=false -c core.eol=lf archive` нужен для проверки неизменности production Compose. Перед установкой сверить байты helper/Compose с Git: обычный Windows archive может преобразовать текст в CRLF. Исходники не содержат секретов и не заменяют рабочую копию. Рабочая директория systemd остаётся прежней.
3. Подготовить защищённый каталог исходников и запустить reviewed `deploy/release-098.py` через отдельную transient systemd-единицу, независимо от SSH. Каталог `release098-<run>` создаёт исключительно сам helper; заранее его не создавать и старый run не переиспользовать. Docker передаёт защищённый env-файл штатному приложению без чтения значений агентом.
4. Остановить writer, получить свежий согласованный снимок всех восьми таблиц, проверить архив offline и реально восстановить его в новый пустой `qa095-098-<run>-` префикс. CLI проверяет схему и SHA каждой таблицы после восстановления. Рабочий restore не выполняется.
5. Запустить 0.9.8 с запретом записи и выключенным Disk recovery. Проверить version/revision/readiness, freeze handshake и полное равенство SHA таблиц свежему снимку. Только затем открыть запись и восстановить restart policy в Compose и Docker.
6. Проверить доверенный HTTPS, точную версию, публичные пользовательские сценарии и сохранность Nginx/TLS/таймера продления. Записать фактический результат ниже. Обычное выключение ПК разрешено только после приёмки и сохранения отчёта.

## Восстановление

Для повторного переключения baseline — принятый образ 0.9.8 `8cb60c82fe5c087aa711b5b89a710e51893649eee7d4462e584e0f716d060e32`, revision `5da7cd0e3f80ccc2df360da372cef4cc113b784a`, run `f098n24a`. Новый helper проверяет его accepted proof, точные байты override и pin25, labels/restart/freeze до остановки и перед откатом. При отказе блокирует новый gate/restart, останавливает systemd и повторно находит возможный поздний кандидат. Останавливается только exact container ID с нужными image/run label. Удаляется исключительно собственный pin `26-release-098.conf`; pin25 и остальные прежние gates сохраняются. Данные назад не откатываются. Предыдущая процедура 0.9.7→0.9.8 сохранена в Git `0508c1f` и первом release-run.

При SIGKILL или отключении питания transient процесс не может выполнить обработчик. Не запускать скрипт повторно с прежним run ID. Сначала сверить unit/pin, exact image/container/run/restart/freeze и root-only артефакты `/var/lib/canon/release098-<run>/`. Отсутствие accepted.json не доказывает заморозку: сбой мог произойти уже после открытия записи. После подтверждения принадлежности при необходимости остановить точный кандидат и вернуть прежний pin по той же последовательности. Старые tombstone-unaware 48ce/0.9.5 writers запрещены. Рабочие таблицы, резервные копии, TLS и настройки секретов не удалять.
