## Поведение

- Версия читается на тёмном подвале, при наведении и клавиатурном фокусе; плавающий помощник не перекрывает кнопку. Первая и вторая очереди гостиниц имеют разные осмысленные пиктограммы.
- Утверждения о 336 местах первой очереди, 3 064 второй и 3 400 в целом проверяются по отдельным полям утверждённого паспорта. Правильный показатель становится зелёным, противоречащий — красным. Исправление 9 999 → 3 400 вне прямой речи применяется точечно, затем проверяется весь новый текст. Цитаты и авторская структура сохраняются.
- Отчёт исходника и результаты новой редакции разделены. Все три счётчика новой редакции видны одновременно; в компактном списке сохраняется пример каждого присутствующего уровня. Версии и поля источников не теряются в wire validation.
- Помощник отвечает по существу и даёт ссылки на версии. Полное исходное поле раскрывается отдельно. Ясные вопросы о площади не требуют повторно назвать кампус: при отсутствии площади в текущем паспорте это прямо указано. Вопросы о проживании, очередях гостиниц и А5 используют правильный показатель и его оговорки.
- Для обзорного ответа модель выбирает и упорядочивает проверяемые серверные формулировки; произвольный неподтверждённый текст и чужие идентификаторы отклоняются. Пустые подписи URL в конце описания исключены из краткого ответа; полная цитата сохранена. Аналитика не менялась.

В текущем рабочем паспорте общей площади нет. Значения 114/123 тыс. м² нельзя подтверждать по старому демонабору. Подтверждение названия не подтверждает весь текст. Прогнозы, прошлые периоды, условия, другой кампус/владелец гостиниц и неоднозначные или предварительные строки требуют отдельной опоры. Ограниченная проверка не доказывает истинность любого произвольного текста.

До исправления воспроизведены: контраст1.08:1; перекрытие версии на768/1280px; одинаковые SVG; верная вторая очередь оставалась yellow; rewrite9999 возвращался неизменным; повторная проверка не передавала собственные findings; ясный вопрос помощнику давал уточнение. Новые проверки сначала обнаружили дефекты, затем прошли после изменений.

Независимое ревью обнаружило и потребовало исправить дополнительные контексты: исторические/гипотетические заголовки, другой владелец, противоречащая или неразбираемая дублирующая строка паспорта, модальность самого источника, sparse AI projection и привязка результата к первой посторонней цитате. Исправления повторно проверены независимо. ## Совместимость и выпуск

Схема БД/роли/рабочие карточки не меняются, миграция не требуется. `rewriteCheck.findings`, finding.sourceField и assistant.presentation — совместимые дополнительные поля. Старый summary-only rewrite и legacy quotes сохраняются. После ожидания ИИ сверяется полный approved source snapshot; добавленная, удалённая или изменённая карточка отменяет прежний proof. Demo использует те же чистые алгоритмы, сохраняя изоляцию от рабочих API/ИИ/записей.

Новый одноразовый [release-099.py](../deploy/release-099.py) рассчитан только на принятую0.9.8/runf098n24b/pin26. План нового запуска: `f099n24a`, pin27-release-099.conf. Старый helper098 повторно не запускается. Источник для ВМ — Git LF archive точного проверенного SHA; Windows CRLF-копия не подходит для checksum Compose.

До переключения: точный CI image/revision/version, свободное место, fresh stopped-writers snapshot, offline verify, реальный restore в отдельные QA-таблицы, затем frozen запуск и byte/hash inventory всех рабочих таблиц. Только после совпадения — открытие записи/Disk recovery и healthy/unless-stopped. Helper требует192MiB резерва после загрузки образа. Широкое удаление Docker-образов/данных не выполняется. Доверенный TLS/Nginx/таймер продления сохраняются.

При обычном отказе кандидат останавливается, rollback только к принятой совместимой0.9.8 без перезаписи рабочих данных. Tombstone-unaware0.9.5/48ce запрещены. SIGKILL/отказ самого rollback требует проверки действительного контейнера и gate/freeze состояния; отсутствие accepted.json само по себе не доказывает закрытие writer. Run ID после создания каталога повторно не используется.

SSH восстановлен запуском существующего ssh-agent; ключ использован без чтения или вывода секрета. После фактической приёмки, сохранения доказательств и документов поручено обычное выключение локального Windows: `shutdown.exe /s /t 0`, без `/f`. ВМ остаётся работать.
