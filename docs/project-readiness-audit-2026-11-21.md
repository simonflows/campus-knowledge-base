# Аудит качества и готовности «Канона»

21 ноября 2026 года. Проверена основная рабочая копия `mlnkws-campus-knowledge-base-main` на локальном коммите `a7b99a0`. До аудита в Git не было незакоммиченных изменений. Локальная ветка `main` опережала сохранённую ссылку `origin/main` на два коммита. Отдельную демоверсию в соседней папке в оценку не включал.

## Решение о запуске

| Режим | Оценка | Решение |
| --- | ---: | --- |
| Локальный показ | 90–95% | Готов на тестовых данных. |
| Закрытый технический пилот | 75–80% | Можно разворачивать на отдельной VM с ограниченным доступом и тестовыми данными. Сборка проверена на Windows, запуск контейнера и VM остаются частью пилота. |
| Публичный режим и сдача по ТЗ | Около 70% | Отложить открытие доступа и загрузку рабочих материалов до закрытия рисков и проверки облачного контура. |

Качество реализации для текущего масштаба оцениваю в **7,5 из 10**. Около 70% — экспертная оценка до публичной сдачи. В ней учтены функции (85/100 с весом 30%), безопасность и достоверность данных (60/100 с весом 25%), эксплуатация (45/100 с весом 25%) и проверяемость (85/100 с весом 20%). Средневзвешенный балл — 68,75. Процент помогает оценить объём оставшейся работы. Условия допуска выполняются каждое отдельно.

## Что работает и как написано

- **Справочник и поиск.** Есть дерево семи вузов, карточки, типы карточек, раздел совместных проектов и серверные правила видимости. Публичный результат ограничен разрешённой версией материала. Это удачный способ держать общую базу фактов и редактировать её без немедленной подмены утверждённого текста. [Справочник](../app/knowledge/page.tsx), [видимость и редакции](../lib/knowledge-lifecycle.ts), [поиск](../app/api/search/route.ts)
- **Редакционный процесс.** Черновик, версии, передача на согласование, возврат, утверждение и DOCX работают на свежей production-сборке с временной базой. Сервер запрещает самосогласование, проверяет текущую версию и пишет связанные изменения транзакцией. Тесты одновременного сохранения и запросов воспроизводимы. [Правила редактора](../lib/editorial.ts), [модель редактора](../lib/editorial-models.ts), [сквозная проверка](../scripts/run-pilot-qa.ts)
- **Фактчекинг и аналитика.** Основные контуры, цифры и статусы проверяются локальным движком по карточкам. Есть регрессии для ошибок из ТЗ, неподтверждённых цифр и разных вузов. Достоверность на широком наборе реальных редакционных материалов предстоит подтвердить с владельцами данных. [Фактчекинг](../lib/fact-check.ts), [регрессии](../scripts/test-university-facts.ts), [аналитика](../lib/analytics.ts)
- **Архитектура.** Next.js объединяет интерфейс и API, а в `lib` вынесены правила доступа, редакционный процесс и модели данных. Для команды и объёма пилота такая схема разумна. Слабое место — крупные модули со многими обязанностями. Рабочая область редактора занимает около 1 550 строк, фактчекинг около 1 700, общие модели около 835. Изменения в них требуют особенно точных регрессий. [Редактор](../components/editor/smart-editor-workspace.tsx), [фактчекинг](../lib/fact-check.ts), [модели](../lib/models.ts)
- **Базовая защита.** На проверенных маршрутах права проверяются сервером. Есть подписанные сессии на восемь часов, отзыв сессии при изменении записи пользователя, защищённая cookie, проверка происхождения запросов записи, валидация входных данных и блокировка анонимных платных вызовов. Production Compose отключает демовход, запускает приложение без root и выставляет порт 8080 только на loopback. [Сессии](../lib/auth-server.ts), [вход](../app/api/auth/session/route.ts), [облачное сравнение](../app/api/benchmark/route.ts), [Compose](../deploy/compose.prod.yml)

## Что исправить до рабочего доступа

### Высокий приоритет

1. **Ограничить отладочный мост браузера.** Он подключается на всех страницах. Команды из другого окна проходят без проверки доверенного домена и отправителя. Навигация принимает адрес без ограничения на сайт приложения. При наличии связи между окнами возникают риск посторонней навигации и риск раскрытия адреса страницы и диагностики. Для рабочей сборки отключить мост, для предпросмотра проверять домен и окно в обоих направлениях. Вывод основан на исходниках. [Подключение](../app/layout.tsx#L79), [канал](../lib/bridge/channel.ts#L48), [навигация](../lib/bridge/router.ts#L45)
2. **Сохранить достоверность при отказе базы.** Фактчек, генерация и публичная выдача карточек способны вернуться к встроенным примерам после проблем с хранилищем и отдать успешный ответ. Редактор может принять такие сведения за актуальную базу. Отдельно нужен мониторинг готовности, потому что `/api/health` отвечает HTTP 200 даже с `database: disconnected`, а Docker проверяет только HTTP-код. Сохранить проверку жизни процесса и добавить проверку готовности хранилища. В рабочем режиме сообщать об отказе либо явно показывать возраст и происхождение резервного снимка. [Фактчек](../app/api/fact-check/route.ts#L14), [генерация](../app/api/editor/generate/route.ts#L34), [карточки](../app/api/knowledge/cards/route.ts#L27), [health](../app/api/health/route.ts#L4), [Dockerfile](../Dockerfile#L47)
3. **Разобрать права на старые карточки.** Два человека с одним вузовским профилем наследуют псевдоним владельца этого профиля. Если старая карточка привязана к нему, при выполнении остальных условий оба могут получить право правки, даже когда их имена различаются. Перед выдачей доступа нужно проверить такие совпадения. Долговременное решение — привязка к постоянным ID пользователей с миграцией и сверкой существующих записей. [Персональный реестр](../lib/pilot-auth.ts#L38), [проверка владельца](../lib/auth.ts#L442)
4. **Утвердить стартовый набор знаний до открытия сайта.** Главная страница и API карточек вызывают автоматическое начальное наполнение. Пустая база может получить исходный корпус при первом чтении. Старые карточки без статуса считаются утверждёнными. Провести сверку с вузами и переносить одобренный набор отдельной управляемой операцией. [Главная](../app/page.tsx#L14), [начальное наполнение](../lib/models.ts#L340), [статус карточки](../lib/knowledge.ts#L366)

### Средний приоритет

5. **Измерить стоимость поиска и истории.** Поиск загружает набор карточек целиком. Список черновиков, история редакций и межвузовские запросы читают таблицы целиком или делают серию дополнительных чтений. Проверить реальные объёмы и нагрузку на плановых 20 и 40 одновременно активных сотрудниках. При превышении целевого времени перейти к выборкам по ключам и постраничной выдаче на горячих маршрутах. Двести выданных аккаунтов и двести одновременных пользователей требуют разных испытаний. [Поиск](../app/api/search/route.ts#L24), [черновики](../lib/editorial-models.ts#L37), [запросы](../lib/information-requests-models.ts#L48), [профиль нагрузки](../plan.md#L104), [тарификация Document API](https://yandex.cloud/ru/docs/ydb/pricing/ru-docapi)
6. **Проверить задержку и восстановление выгрузки на Диск.** Выгрузка запускается внутри ответа на согласование, перечитывает корпус и отправляет несколько файлов. Есть сохранённое состояние попытки, версии и ручной повтор. Проверить частичную ошибку и доступность последней успешной версии. При нестабильности вынести выгрузку и повторы из пользовательского запроса и добавить оповещение об отставании. [Согласование](../app/api/knowledge/cards/%5Bid%5D/moderation/route.ts#L136), [синхронизация](../lib/disk-sync-service.ts), [запись файлов](../lib/yandex-disk.ts#L598)
7. **Уточнить правила для общих компьютеров и ограничения входа.** Восстановление хранит полный несохранённый черновик в браузере. Семидневный срок проверяется при следующем чтении, а сессия на сервере заканчивается раньше. Для общих устройств определить режим без долговременной локальной копии. Для нескольких реплик учитывать, что ограничение попыток входа в приложении действует в пределах одного процесса, и проверять лимит и корректность IP на доверенном прокси. [Локальное восстановление](../lib/editorial-recovery.ts#L58), [ограничение входа](../lib/auth-server.ts#L46), [Nginx](../DEPLOY.md#L241)
8. **Проверять именно выпускаемый образ.** GitHub Actions проверяет код, типы, YAML Compose, preflight, офлайн-регрессии и сборку Next.js. В workflow нет старта Docker-образа и сквозного набора `test:fixture`. SourceCraft CI содержит заглушку. Нужно проверить сборку и запуск образа на Linux, выполнить сквозной набор в CI и установить обязательный статус для защищённой ветки. Наличие локального YAML не подтверждает состояние удалённой защиты. [GitHub Actions](../.github/workflows/ci.yml#L34), [SourceCraft](../.sourcecraft/ci.yaml), [состав тестов](../package.json), [обязательные статусы GitHub](https://docs.github.com/en/pull-requests/reference/status-checks)

## Порядок работ перед выпуском

1. Закрыть отладочный мост, явное поведение при отказе базы и допуск исходных карточек и персональных прав. Добавить регрессии для этих сценариев.
2. Запустить тот же SHA на закрытой VM. Проверить Docker, Nginx, HTTPS, ограничение доступа к порту и права приложения на чтение и запись в отдельной YDB. Включить наблюдение за состоянием базы и ошибками. [Самостоятельное размещение Next.js](https://nextjs.org/docs/app/guides/self-hosting), [транзакции YDB Document API](https://yandex.cloud/ru/docs/ydb/docapi/api-ref/actions/transactWriteItems)
3. Восстановить тестовую копию всех шести таблиц и сверить данные. Проверить реальный Яндекс Диск и доступ к файлам во время остановки тестового приложения. Выполнить сравнение ИИ на открытых материалах, если сдаётся полный объём ТЗ.
4. Пройти редакционный сценарий с сотрудниками разных вузов и согласованную нагрузку. Зафиксировать результаты для выпускаемого SHA, обязательный CI, порядок отзыва доступа и отката. После этого принимать решение о расширении доступа.
