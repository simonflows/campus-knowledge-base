# Канон кампуса «Южный Урал»

Единая каноническая база знаний (Single Source of Truth), умный SEO/GEO-редактор, детерминированный фактчекинг и сборная аналитика для семи вузов-резидентов Межуниверситетского кампуса мирового уровня «Южный Урал» (Челябинск), концессионера ООО «ЧКК», АНО «РИОН» и Министерства образования и науки Челябинской области.

Ветка выпуска **0.9.5**: [руководство по новым сценариям](docs/release-0.9.5-guide.md), [актуальное состояние](progress.md), [приёмка](docs/release-0.9.5-validation.md), [совместимость и миграция](docs/release-0.9.5-data-migration.md), [полный backup/restore](docs/release-0.9.5-backup.md). Номер в исходниках не подтверждает развёртывание; рабочий SHA и образ фиксируются по результатам выпуска.

## Назначение и решаемые задачи

Сервис создан для координации публичного инфополя кампуса «Южный Урал» и устранения расхождений в цифрах, статусах строящихся объектов, наименованиях лабораторий и авторстве совместных разработок между семью вузами-участниками (ЮУрГУ, ЧелГУ, МИДиС, ЮУГМУ, ЮУрГАУ, МГТУ им. Г. И. Носова, ЮУрГГПУ).

Основные функции:
- Хранение верифицированных карточек кампуса, лабораторий, проектов, образовательных программ и пользовательских сущностей в единой иерархии папок с автоматическим резервным копированием на Яндекс Диск.
- Конструктор типов карточек без участия программиста для расширения структуры данных по мере согласования форматов с Минобрнауки Челябинской области.
- Автоматический фактчекинг черновиков по 6 контрольным точкам и 66 правилам контент-аудита («Светофор» + переписывание по канону).
- Умный редактор, формирующий SEO/GEO-материалы строго из проверенных фактов карточек (Слой 1) с опорой на смысловые чанки утверждённых статей (Слой 2).
- Детерминированная сборная аналитика по отраслям, вузам, индустриальным партнёрам и стадиям готовности без домысливания.
- Дополнительный демонстрационный контур (`NEXT_PUBLIC_DEMO_MODE=true`) со страницей архитектурного сравнения (`/comparison`) и панелью состояния интеграций.

## Архитектура данных и резервирование на Яндекс Диске

### Два уровня знаний
- **Слой 1 — Канонические карточки**: единственный источник твёрдых фактов (площади, стоимость, сроки очередей, статусы лабораторий «Действует на площадке вуза» / «Планируется к открытию в УНК», соавторство проектов).
- **Слой 2 — `Готовые_статьи/`**: библиотека утверждённых материалов, разбитых на самодостаточные смысловые чанки для переиспользования живых формулировок.

### Дерево папок
- `00_Кампус_общие_параметры/` — единый паспорт кампуса `CAMPUS-PASS-001`, очереди ввода, юрлица, тарифы и стоп-лист ошибок.
- `01_Вузы_резиденты/` — отдельные папки для всех 7 вузов (ЮУрГУ, ЧелГУ, МИДиС, ЮУГМУ, ЮУрГАУ, МГТУ им. Г. И. Носова, ЮУрГГПУ) с подпапками `Паспорт_и_спикеры/`, `Инфраструктура_и_лаборатории/`, `Продукты_и_проекты/`, `Партнёры_и_соглашения/`, `Готовые_статьи/`.
- `02_Совместные_проекты/` — единая карточка межвузовской разработки (например, «Виртуальный тренажёр травмпункта» МИДиС + ЮУГМУ), которая отображается ссылкой в папках обоих вузов.
- `03_custom/` — папки пользовательских сущностей, созданных администратором в Конструкторе типов.

### Хранение и автовыгрузка
- При наличии `DOCUMENT_API_ENDPOINT` сервис использует DynamoDB / Yandex Database Document API. При недоступности рабочей БД интерфейс сообщает о сбое. Локальное демо с сохранением существующего `.data/local-store.json` включается через пункт [6] в `start.bat` или `CAMPUS_LOCAL_DEMO=true` вне production. Файл остаётся на месте при повреждении или неизвестной версии. Предыдущая корректная запись сохраняется в `.data/local-store.json.bak`. Совместная редактура и межвузовские запросы требуют Document API.
- При утверждении карточки или сохранении статьи система формирует Markdown-паспорт и сводный CSV-реестр и отправляет их на Яндекс Диск (если задан `YANDEX_DISK_OAUTH_TOKEN`). Дополнительно любую карточку и статью можно скачать в `.md` прямо из интерфейса.

## Роли, права доступа и защита API

В системе реализованы 7 ролей из ТЗ (`lib/auth.ts`):
1. **Администратор канона (`admin`)**: ведёт всю базу, модерирует черновики, управляет конструктором типов и общим паспортом `00_Кампус_общие_параметры/`, очищает стартовые демо-статьи.
2. **Министерство образования и науки (`ministry`)**: чтение, фактчекинг, генерация статей, аналитика, отправка запросов на правку владельцу.
3. **АНО «РИОН» (`rio`)** и **Концессионер ООО «ЧКК» (`chkk`)**: редактирование карточек в своей зоне ответственности и запросы на правку чужих карточек.
4. **Владелец карточки в вузе (`university_owner`)**: создание и редактирование карточек своего вуза, подтверждение участия в совместных проектах.
5. **PR-команда / редактор вуза (`university_pr`)**: подача черновиков (попадают на модерацию координатору), работа со статьями своего вуза в `Готовые_статьи/`.
6. **Гость (`guest`)**: только чтение утверждённого канона, фактчекинг и аналитика без прав изменения или удаления.

Реализованные механизмы защиты (`lib/auth-server.ts`, маршруты `app/api/**`):
- В пилоте сотрудник входит по персональному логину и сгенерированному ключу. Права определяет серверный справочник. Два сотрудника одного вуза имеют разные личные черновики и историю действий.
- Сервер проверяет подпись HMAC-SHA256 и срок сессии восемь часов. Кука `__Host-vibecraft-session` имеет атрибуты `HttpOnly`, `Secure`, `SameSite=Lax` и `Path=/`. Отзыв учётной записи или смена персонального ключа прекращает действие выданных сессий при следующем запросе.
- После пяти неудачных входов за пять минут приложение возвращает 429. Изменяющие запросы защищены проверкой источника.
- Серверная изоляция по `universityId`: представитель одного вуза не может создавать карточки или статьи в папке другого вуза и не может удалять чужие материалы (`403`).
- Alibaba Cloud Model Studio доступна в полигоне на фиксированном наборе открытых сведений. Запросы сотрудников, рабочие карточки, контакты и черновики статей в этот API не отправляются.

## Фактчекинг (66 кейсов аудита) и стандарты SEO/GEO

Модуль `/check` (`lib/fact-check.ts`, `lib/audit-canon-registry.ts`) сверяет тексты по 6 контрольным точкам:
1. Общие параметры кампуса (`121,8–123 тыс. м²` / `122 863,3 м²`, бюджет `16,75 / до 34,6 млрд руб.`, 3 очереди `2024 / 2026 / 2027–28`, `3 400` мест и `5 000` обучающихся, разделение региональных `8 программ / 83–84 решения` и федеральных `37 / 245` по 5 пилотным регионам).
2. Статус и размещение лабораторий (запрет выдавать планируемые лаборатории УНК 2027 года за уже действующие).
3. Авторство и соисполнители совместных проектов (`МИДиС + ЮУГМУ`, `ЮУрГУ + МГТУ им. Г. И. Носова`).
4. Разделение контуров (кампус / ПИШ / УМНОЦ / собственный проект вуза).
5. Официальные наименования юрлиц, вузов и спикеров (перехват опечаток из аудита: «ВТД Девелопмент», «ЮУрГППУ», «робот Куки», «кинопласт», «6 вузов»).
6. Неподтверждённые количественные метрики (жёлтый уровень предупреждения).

При нажатии «Переписать по канону» система исправляет ошибки и перестраивает материал по требованиям SEO и GEO: сильные первые 1000 знаков с ключевыми фактами, иерархия `H1–H2–H3`, самодостаточные чанки по 1–2 абзаца и список карточек-источников. Движок устойчив к ReDoS: проверка текста длиной 58 000 символов выполняется быстрее 250 мс.

## Переменные окружения и режимы работы

Для локального просмотра через `start.bat` ключи не требуются. Оператор задаёт серверные переменные в защищённой форме VibeCraft или хранилище секретов платформы. После обновления среды перезагрузите страницу, чтобы увидеть состояние интеграций. Порядок выдачи персонального доступа и отзыва ключей приведён в [инструкции оператора](DEPLOY.md#pilot-access).

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `YANDEX_AI_STUDIO_API_KEY` | API-ключ Yandex Cloud для YandexGPT | Не задан (локальный канонический движок) |
| `YANDEX_AI_STUDIO_FOLDER_ID` | ID каталога в Yandex Cloud | Не задан |
| `YANDEX_DISK_OAUTH_TOKEN` | OAuth-токен Яндекс Диска для автобэкапа `.md` и `.csv` | Не задан |
| `ALIBABA_DASHSCOPE_API_KEY` | Ключ Alibaba Cloud Model Studio (Qwen) | Не задан |
| `ALIBABA_MODEL_NAME` | Имя модели Qwen | `qwen-plus` |
| `SESSION_SECRET` | Общий для экземпляров приложения секрет HMAC от 32 символов | Обязателен в пилоте и production |
| `CAMPUS_PILOT_ACCOUNTS` | Серверный JSON со связкой логин, имя, профиль и отпечаток ключа | Пилотный вход закрыт до настройки |
| `CAMPUS_DEMO_LOGIN` | Серверное разрешение демонстрационного входа по ролям | Выключено. Локальный dev-запуск через `start.bat` включает его на loopback |
| `CAMPUS_PUBLIC_ORIGIN` | Внешний HTTPS-адрес приложения для ссылок на источники в Word | Адрес текущего запроса |
| `ADMIN_ACCESS_PIN` | Дополнительный ПИН демонстрационного администратора | Применяется только при разрешённом демо-входе |
| `SEED_DEMO_ARTICLES` | Установите `false`, чтобы отключить начальные статьи в явном локальном демо | `true` для демо |
| `NEXT_PUBLIC_DEMO_MODE` | Установите `true`, чтобы показать в интерфейсе раздел «Архитектура и ИИ» (`/comparison`), кнопку «Интеграции» и выбор ИИ-движка в редакторе | `false` |
| `DOCUMENT_API_ENDPOINT` | Endpoint DynamoDB / Yandex Database Document API | Без настройки рабочая база недоступна |
| `CAMPUS_PREVIEW_ORIGIN` | Точный origin доверенного предпросмотра в development | Мост выключен |
| `CAMPUS_LOCAL_DEMO` | Явно включает сохранение прежних локальных данных; только вне production | `false` |

## Локальный запуск, Docker и проверка качества

### Быстрый запуск на Windows
Откройте `start.bat` в корне проекта (или внутри папки приложения). Интерактивный лаунчер (`scripts/start-launcher.mjs`) автоматически установит зависимости при необходимости, проверит порт `8080` и предложит:
- `[1]` Запуск dev-сервера на `http://localhost:8080`
- `[2]` Production-сборка и запуск (`npm run build` + `start`)
- `[3]` Прогон всех тестов, линтера, проверки типов и сборки
- `[4]` Список переменных для подключения интеграций (`npm run setup`)
- `[5]` Запуск через Docker Compose с локальной DynamoDB (`http://localhost:8080`)
- `[6]` Локальное демо: существующий `.data/local-store.json` сохраняется; совместная редактура и межвузовские запросы требуют Document API.
- `[7]` Полное локальное демо с черновиками, согласованием и межвузовскими запросами на [127.0.0.3:8080](http://127.0.0.3:8080). Команда `start.bat --full-demo` запускает демо напрямую. Повторный выбор `[7]` открывает уже запущенное полное демо. На экране входа выберите демонстрационную роль.

Для пункта `[7]` один раз распакуйте [Windows x64 JDK 21](https://adoptium.net/temurin/releases/?version=21&os=windows&arch=x64&package=jdk) в `%LOCALAPPDATA%\CampusKnowledgeDemoTools\jdk` (должен быть файл `bin\java.exe`) и [DynamoDB Local 3.3.2](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamoDBLocal.DownloadingAndRunning.html) в соседнюю папку `dynamodb` (с `DynamoDBLocal.jar` и `DynamoDBLocal_lib`). Для других папок задайте абсолютные пути `CAMPUS_DEMO_JAVA` до `java.exe` и `CAMPUS_DEMO_DYNAMODB` до папки DynamoDB Local.

Записи полного демо сохраняются в `%LOCALAPPDATA%\CampusKnowledgeDemoData\shared-local-instance.db` между запусками. Сервисы доступны через loopback, внешние БД, ИИ и Яндекс Диск в этом режиме отключены.

### Запуск из терминала
```bash
npm install
npm run dev
```
Сервис откроется на `http://localhost:8080`. При недоступности рабочей базы справочник и редактор показывают сообщение о проблеме. Для показа на встроенных примерах выберите пункт `[6]` или `[7]` в лаунчере.

### Запуск в Docker
```bash
docker compose up --build
```
Сервис будет доступен на `http://localhost:8080`. Для подключения облачных сервисов менеджер секретов оператора передаёт перечисленные выше переменные процессу Docker Compose.

### Проверка кода и тесты

```bash
npm run test:offline
npm run check
npm run build
```

`test:offline` проверяет права и срок сессии, семь вузов, разбор фактов, поиск, редактуру, отказ хранилища, Диск с тестовым транспортом и сценарии сравнения ИИ. Подключение к облаку не требуется.

**Проверка пилота в отдельной базе.** Запустите пустую одноразовую DynamoDB Local в памяти командой `docker compose -f deploy/compose.qa.yml up --detach` на тестовой машине. Нужны собранное приложение, свободный адрес `127.0.0.2:8080` и Chrome. Для установленного Edge задайте `CAMPUS_QA_CHROME_CHANNEL=msedge`. Пример PowerShell использует специально выделенные фиктивные реквизиты.

```powershell
$env:CAMPUS_QA_DISPOSABLE = "yes"
$env:USE_DATABASE = "true"
$env:DOCUMENT_API_ENDPOINT = "http://127.0.0.1:8000"
$env:DOCUMENT_API_REGION = "us-east-1"
$env:AWS_ACCESS_KEY_ID = "campusLocalTest"
$env:AWS_SECRET_ACCESS_KEY = "localTestOnly"
$env:CAMPUS_QA_MARKER = (npm run --silent qa:init-fixture).Trim()
npm run check:deploy-storage
npm run test:fixture
```

`qa:init-fixture` создаёт схему только в пустой тестовой базе, добавляет тестовый корпус и выдаёт уникальный маркер. Тесты записи проверяют маркер, HTTP-тест проверяет его через портал. `test:fixture` проверяет роли, согласование, Word, привязку владельца, мобильный входящий запрос и ограничения облачного сравнения. Все записи остаются в одноразовой базе.

Чтобы измерить чтение и сохранение черновиков на тестовой сборке, задайте `CAMPUS_QA_MEASURE_LOAD=smoke` для трёх коротких циклов на ступенях 20 и 40. Значение `pilot` запускает 30 минут на первой ступени и 10 минут на второй. Тест проверяет сохранённые записи по повторному чтению. Этот профиль измеряет loopback и временную базу. Приёмка реальной нагрузки через Nginx и YDB описана в [plan.md](plan.md#проверка-и-масштабирование).

## Памятка для сотрудников 7 вузов

1. **Проверка перед публикацией**: вставьте черновик пресс-релиза на странице `/check` и нажмите «Проверить текст» (или «Переписать по канону»). Публикация разрешена только при отсутствии красных флагов.
2. **Подготовка новой статьи**: откройте `/editor`, сформулируйте задачу свободным языком или выберите смысловой блок из уже утверждённой статьи в библиотеке как опору. Перед сохранением в `Готовые_статьи/` можно вручную отредактировать заголовок H1, лид и каждый чанк.
3. **Работа с базой карточек (`/knowledge`)**:
   - Не дублируйте межвузовские разработки в личных папках — размещайте их в `02_Совместные_проекты/` с указанием обоих вузов.
   - Для лабораторий обязательно указывайте актуальный статус размещения (действует на площадке вуза или планируется в УНК к 2027 году).
   - Если нашли ошибку в карточке другого вуза, нажмите «Запросить правку» и оставьте комментарий владельцу карточки.
4. **Очистка демо-статей**: перед переводом библиотеки в чистую эксплуатацию администратор может нажать «Очистить демо-статьи (3)» в разделе `/editor` либо задать `SEED_DEMO_ARTICLES=false`.
